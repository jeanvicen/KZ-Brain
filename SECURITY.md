# Segurança

## Estado e escopo

O repositório está em fase documental. Não há runtime de IA, API ou serviço de produção para reportar. Ainda assim, vulnerabilidades em configuração, documentação ou cadeia de contribuição são relevantes.

## Relato responsável

Não publique detalhes exploráveis, segredos ou dados pessoais em issues. Use o canal privado de reporte de vulnerabilidades disponibilizado pelo GitHub para este repositório. Inclua impacto, condições de reprodução, versões/commit e uma forma segura de contato.

## Regras atuais

- Não commitar chaves, tokens, credenciais, dados pessoais, datasets ou checkpoints.
- Tratar referências externas, artefatos e código de terceiros como não confiáveis até revisão.
- Qualquer integração futura precisa de modelo de ameaças, escopo de permissões, gestão de segredos, logs seguros e plano de resposta.
- A ausência de implementação não é certificação de segurança.

## Resposta futura

O processo de triagem deve confirmar recebimento, reproduzir em ambiente isolado, avaliar impacto, preparar correção revisada e comunicar resolução sem expor detalhes desnecessários.
